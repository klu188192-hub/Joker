3. 桌面应用一个 .exe 包含所有 agent (用户买的解锁, 没买的灰显)

### 关键中间件

```python
# 所有 agent 调用都经过这个中间件
@app.middleware("http")
async def auth_and_billing(request, call_next):
    # 1. 验 JWT
    user = await verify_jwt(request)
    
    # 2. 验授权码状态 (未过期, 未冻结)
    if user.expires_at < now():
        return 402  # Payment Required
    
    # 3. 检查配额
    if not await quota_remaining(user.id):
        return 429  # Too Many Requests
    
    # 4. 限流
    if not await rate_limit_check(user.id):
        return 429
    
    # 5. 调用业务
    response = await call_next(request)
    
    # 6. 异步扣额度 + 记日志
    asyncio.create_task(deduct_quota(user.id, request.path))
    
    return response
```

## 🛡️ 多数据源容灾架构

### 实时数据源管理

```python
# api/data/manager.py

class DataSourceManager:
    """3 层降级, 客户无感切换"""
    
    realtime_sources = [
        EasyQuotationSinaSource(),     # 主 (15-30s 延迟)
        EasyQuotationTencentSource(),  # 备 1
        XueqiuSource(),                # 备 2
    ]
    
    historical_sources = [
        TushareProSource(token=TUSHARE_TOKEN),  # 主 (商用合规)
        AkshareSource(),                        # 备 (覆盖广)
    ]
    
    cache = RedisCache(ttl_realtime=30, ttl_historical=300)
    
    async def get_realtime_price(self, symbols: list[str]) -> dict:
        # 1. 缓存
        cached = await self.cache.mget([f"rt:{s}" for s in symbols])
        missing = [s for s, v in zip(symbols, cached) if v is None]
        if not missing:
            return cached
        
        # 2. 按优先级试 source
        for source in self.realtime_sources:
            try:
                data = await source.get_realtime(missing)
                await self.cache.mset(data, ttl=30)
                return {**cached, **data}
            except (RateLimitError, NetworkError, ParseError) as e:
                logger.warning(f"{source.name} failed: {e}")
                continue
        
        # 3. 全挂 → 返回过期缓存 + 警告
        stale = await self.cache.mget(missing, allow_stale=True)
        return {**cached, **stale, "_warning": "实时源临时不可用, 显示 X 分钟前数据"}
```

### F4 警报架构 (真实时)

```
┌──────────────────────────────────────────────────────────┐
│  PostgreSQL · alerts 表                                   │
│  id | user_id | symbol | condition | triggered           │
└────────────┬─────────────────────────────────────────────┘
             │
             │
   ┌─────────▼─────────┐
   │ scheduler 每 30s   │  ← Celery beat 或 APScheduler
   └─────────┬─────────┘
             │
   1. SELECT * FROM alerts WHERE NOT triggered
   2. GROUP BY symbol → 假设 500 只票
   3. data.get_realtime_price([500 只])  ← 1 次请求, 2 秒返
   4. 比对条件 → 触发的 → 异步推送
             │
   ┌─────────▼─────────┐
   │  wxpusher 推送     │ → 用户 5 秒内手机收到
   └───────────────────┘
```

**实测成本**:
- 1000 用户 × 5 警报 = 5000 警报
- 去重后 500 只票
- 每 30 秒 1 次请求 = 2880 次/天
- easyquotation 单次拉多只, 新浪不会封

## 🔐 安全设计

### 鉴权 5 层防御

```
1. HTTPS (Let's Encrypt 证书)
2. JWT (24h 有效期, 自动刷新)
3. 授权码 + 设备指纹绑定 (一码一机)
4. 服务端 expires_at 检查 (每次调用)
5. 关键 LLM 调用必经 L2 中转 (本地破解无意义)
```

### 防破解 (做到 80% 够用)

| 攻击 | 防御 | 强度 |
|---|---|---|
| 改本地代码绕过授权 | LLM 必走中转, 403 直接拒 | ⭐⭐⭐⭐ |
| 共享授权码 | 设备指纹 + 1 码 1 机 | ⭐⭐⭐ |
| 抓包伪造 | HTTPS + JWT + 时间戳签名 | ⭐⭐⭐⭐ |
| 反编译 | pyarmor 混淆 | ⭐⭐ |


## 🎯 复核 #2 · 2026-05-30 · v2 评分 6.5/10

**Joker 态度**: 收到 DeepSeek 关切, 但**不阻塞 v1.0 推进**. 决策原则: 先成型, 我作为真实用户体验, 体验后再调架构.

### DeepSeek 一句话: "从必死无疑 (5.5) 提升到九死一生 (6.5). 方向对了, 但合规与获客两个命门依然悬而未决."

### v1 → v2 风险解决度

| v1 风险 | v2 解决度 | DeepSeek 判断 |
|---|---|---|
| 1. 下沉市场 + 桌面应用矛盾 | ✅ **真解决** | "中端散户重定位是 v2 最大价值" |
| 2. 小程序金融审核必拒 | ⚠️ 化妆遮掩 | "线上+线下双路径是掩耳盗铃, 个人微信收款是灰产" |
| 3. 续费率伪需求 | ⚠️ 升级为"高门槛需求" | "用户凭什么先信任你, 上传交易记录?" |
| 4. PyInstaller UI 灾难 | ⚠️ 降为隐患 | "shadcn 解决 UI, 但杀毒报警/启动慢/打包大未解决" |
| 5. API 成本倒挂 | ❌ 未解决 | "多数据源容灾运维成本翻倍, 高频用户月成本可能超 ¥100" |

### v1 三盲点 (v2 全部未解决)

1. **证券投资咨询资质** — 法律实质判断"用户依赖度", 免责声明无效
2. **数据二次商用** — Tushare/akshare/雪球协议禁止商用, 沙滩上的城堡
3. **获客成本严重低估** — 金融领域 CPA ¥200-500/人, ¥9.9 体验装是负资产

### v2 新引入风险

1. **工程复杂度爆炸** · 4 周做基础设施, 然后无 MVP 可演示
2. **"中端散户"画像不精准** · 可能更信"老师"而非 AI
3. **F4 实时警报可靠性** · 15-30s 延迟在闪崩行情可能是法律和口碑炸弹

### 最危险节点 + DeepSeek 建议

**节点**: W4 → W5 转换时 (4 周做基础设施, 无 MVP 验证)

**DeepSeek 反方案** (供未来体验后参考):
1. 砍 Phase 1 的桌面壳 + 多数据源容灾, MVP 用 Streamlit Cloud Web 版
2. Phase 2 顺序改成 F2 (复盘) → F1 (选股), 砍 F3/F4 到后期
3. W3 必须有"最小可演示原型" (上传交易记录 → 周报)
4. 拿原型给 10 个朋友测付费意愿, < 3 人愿付立刻止损

## 🛡️ Joker 的对冲策略 (针对 DeepSeek 关切)

### 关于合规
- 短期: 严守 "AI 学习辅助" + "不构成投资建议" 话术
- 中期: v1.0 成型后, 如果有真实付费用户 → 评估申请投资咨询资质 (券商通道)
- 长期: 极端情况转纯线下卖 (面对面 / 朋友 / 沙龙), 框架支持

### 关于续费 / 获客
- v1.0 阶段不追求规模, 只验证 "Joker 自己用 + 5-10 朋友用" 是否有真实价值
- 不投放, 不付费引流, 只通过自然口碑增长
- 续费数据 → 真实告诉我们护城河是否成立

### 关于 API 成本
- 严格每用户每月配额上限
- Redis 缓存复用相同标的的近期分析 (大幅降 token)
- DeepSeek 跑不动时降级 Gemini Flash (免费 1500 次/天)
- 月度 dashboard 监控 token / 用户成本比

### 关于实时性
- F4 警报话术加 "建议作为辅助参考, 实际操作以您交易软件实时数据为准"
- 不承诺低延迟 SLA
- 推送日志全留, 极端情况能审计

## 🛠️ 复核 #3 · 2026-05-30 · 工程层 6.5/10

**评估角度**: Senior Backend Engineer + SaaS CTO
**一句话**: "思路清晰、结构良好, 但略显学院派. 500-1000 用户天花板, 上 1000 必须重构."

### 各维度评分

| 维度 | 分 | 评语 |
|---|---|---|
| 架构合理性 | 7 | 4 层清晰 + 多源容灾是亮点, 但中间件链同步阻塞需重构 |
| 技术选型 | 7 | FastAPI + asyncpg + Redis 黄金组合, 但 Streamlit + PyInstaller 是最大坑 |
| 数据库设计 | 8 | 15 表规范, 但**索引缺失致命** (alerts/quota_usage/sessions) |
| 可扩展性 | 5 | 1000 用户天花板, 瓶颈在 DB + 单机 |
| 运维成本 | 4 | 单机 + 自建 PG 无主备, SPOF 多 |
| 测试覆盖 | 8 | 70% + Playwright 标准, 重点放中间件/容灾/调度/配额 |
| 代码质量 | 9 | ruff + mypy strict + Actions 顶级配置 |

### 🔴 必须立刻改 (Phase 1 W1-4 前)

1. **数据库索引** (alerts `status=1` 全表扫 = 5000 警报时崩) → ✅ **Day 2 已补**
2. **APScheduler 在 Uvicorn worker 里** = SPOF + 多 worker 重复触发
   - 方案: 独立进程跑 + Redis 分布式锁 `SETNX` 抢主
   - 时点: Day 7 实现警报时按这个做
3. **中间件 `asyncio.create_task` 异步火苗**
   - 方案: Redis 同步扣额度 + 异步只写日志 (失败不影响主流程)
   - 时点: Day 4 计费系统按这个做
4. **JWT 必须无状态**
   - 方案: JWT 只验签名 + 过期, 配额限流全走 Redis
   - 时点: Day 3 鉴权直接按无状态实现

### ⚠️ 强烈建议 (但 Joker 决定推迟)

**桌面端选型**: DeepSeek 强烈建议**砍 Streamlit + PyInstaller, 改 Web 版**.

理由 (DeepSeek):
- 体积 >300MB · 启动 >10s · 杀毒报警概率极高
- Web 版所有问题消失

**Joker 决定**: 保留桌面应用, 但**准备 Plan B (Web 版兜底)**. 桌面应用上线后真实用户反馈 → 体验差立刻 1 周切 Web.

### 🟡 可以推迟 (W12-20 优化)

1. **多源容灾"过期缓存兜底"** → MVP 直接报错, 用户量 < 100 不需要这层
2. **Celery 替换 APScheduler** → 用户 500+ 再考虑
3. **PG 主备 (RDS)** → 用户 1000+ 再考虑

### 🚨 SPOF 清单 (优先级排序)

| # | 单点 | 风险等级 | 解决时点 |
|---|---|---|---|
| 1 | ECS 服务器 | 🔴 | 立刻: docker-compose restart:always + systemd 自动重启 |
| 2 | APScheduler 进程 | 🔴 | Day 7: 独立进程 + Redis 分布式锁 |
| 3 | PG 无主备 | 🟡 | W12+: 用户 1000 后上 RDS |
| 4 | Redis 单实例 | 🟡 | W12+: AOF 持久化 + 主从 |

### 🧪 MVP 部署前必做的工程动作 (Phase 1 W4 验收清单)

1. ✅ 所有必须改的 3 件事完成
2. 一键部署 + 恢复脚本 (`deploy.sh` + `restore.sh`)
3. Sentry 告警配置 (致命错误立即推送企微)
4. **压力测试**: Locust 模拟 100 并发 / 10 分钟
   - 验收: 响应时间 < 2s · 错误率 < 0.1%
5. **服务降级页**: 后端宕时 Nginx 返静态页

### 性能瓶颈预测 (按用户量级)

| 用户量 | 第一个崩的 | 缓解方案 |
|---|---|---|
| 100 | DB 连接池 | 调大 pool_size 到 30, max_overflow 50 |
| 500 | APScheduler 单进程 | 独立进程 + 分布式锁 |
| 1000 | PG 单机磁盘 IO | 升级 RDS + 主备 |
| 5000 | 单 ECS CPU | 横向扩展 + 负载均衡 |

### 💡 DeepSeek 反对的几个"过度设计" (我们决定保留 vs 砍掉)

| 设计 | DeepSeek 建议 | Joker 决定 |
|---|---|---|
| `behavior_profile` 表 | 砍, MVP 不需要 | ✅ **保留** (这是 F2 续费命脉) |
| `trade_records` 表 | 砍, MVP 不需要 | ✅ **保留** (这是 F2 数据源) |
| `reports` 表 | 砍 | ✅ **保留** (W7 用) |
| `instructor` 库 | 砍, 直接 Pydantic | ⚠️ **保留但可换** (instructor 真好用) |
| 多源容灾过期缓存 | 砍, 直接报错 | ⚠️ **简化** (MVP 阶段直接报错, 用户量上来加缓存) |

**总原则**: 架构不能砍 (上来再补复杂度高), 但实现可以延后 (空表 + 待 W5 启用).

## 🩹 常见故障对照表

| 症状 | 可能原因 | 排查 |
|---|---|---|
| 测试突然变红 | 改了 Protocol 接口但漏改实现 | `pytest -v` 看具体哪个失败, 跟着错误信息走 |
| `import fakeredis` 失败 | 包没装 | `pip3 install fakeredis aiosqlite` |
| `JSONB compile error` | 在 PG 之外的 DB 上跑 | 看 `api/models.py:JSONB` 是 `with_variant`, 没被改坏 |
| `BigInteger autoincrement` 失败 | 同上, SQLite 主键 | `PK_BigInt = BigInteger.with_variant(Integer, "sqlite")` |
| JWT 401 错 (但 token 看着对) | jwt_secret 改了, 老 token 全失效 | 跑一次 `/auth/activate` 拿新的 |
| Streamlit 启不来 | port 8765 被占 | `lsof -i :8765` 找谁占 |
| `claude --version` 海外 IP 警告 | 代理没启 | 看 `/Users/joker/.claude/CLAUDE.md` 网络出口规则 |
| 某次 CC 改坏 SQL 表 | schema 迁移没跟 ORM 对齐 | `sql/init/01_schema.sql` vs `api/models.py` 对照 |

## 📈 扩展性瓶颈速查 (用户 2026-05-31 担心规模化变慢)

**总结一句**: 0-1000 用户当前架构够, 1000+ 有 P1 清单, 10000+ 水平扩容. 真瓶颈是 LLM API rate limit, 不是我们.

### 4 个瓶颈拆解

| 瓶颈 | 风险 | 我们怎么挡 |
|---|---|---|
| **1. DB 查询 (用户数据增长)** | 无 | schema 是**滑窗**: behavior_profile 1 行 / trade_records 90 天 / chat_history limit 20. O(log n + k) 永远小 |
| **2. LLM Prompt token 爆** | 推理慢+贵 | **input cap 1500-2000 token**: 长期/中期/短期记忆都有滑窗, 用户用 3 年跟第 1 天一样快 |
| **3. 多用户并发** | 0-1k 用户无 | 全异步 (asyncpg+aioredis+httpx) + 连接池 + JWT 无状态 + 分布式锁 |
| **4. LLM 调用本身慢** | 2-5s 体验主因 | **Redis 24h cache** (杀手锏): 1000 人看茅台只调 1 次 LLM, 用户越多人均成本越低 |

### 规模 → 瓶颈 → 对策

| 用户数 | 当前能扛 | 真瓶颈 | 何时做 |
|---|---|---|---|
| **0-100** | ✅ 完全够 | 无 | 现在 |
| **100-1k** | ✅ 够 | DeepSeek API key rate limit | W12 备 2-3 个 key 池 |
| **1k-10k** | ⚠️ 边界 | DB write 压力 + Redis 内存 | **P1 清单**: LLMCall 异步队列写, Redis 加内存或分片 |
| **10k+** | ❌ | 单 ECS 不够 | **P2 清单**: 水平扩 uvicorn 多实例, Redis 集群, PG 主从, 架构原生无状态支持 |

### LLM cache 命中率 (随用户增长**反而提速**)

热门 A 股就那 500 只: 1000 用户看茅台一次, 第 2 次起命中 cache 秒回. 用户**越多, 人均 LLM 成本越低**, 速度越快.

详细技术分析在: `/Users/joker/jokeragent/docs/SCALABILITY.md` (W6 写).

## 痛史 #1: MACD_SSL_v2 未来函数 (2026-05-08) 💀💀💀

### 症状
- 因子库回测显示 **60% 胜率 + +633% ROI** (6 倍)
- 上线后真实表现: **50% 胜率 + 4 年 CAGR -79.8%**
- 32 个实盘 EA 在跑**负期望策略**

### 根因
```python
# fractal swing 计算
fractal(left=3, right=3)
# 然后:
confirm_time = h1.index[i_b]      # ❌ 错!
# 应该是:
confirm_time = h1.index[i_b + right]  # ✅ 对 (i_b + 3 收盘后才能确认 fractal)
```

**3 H1 = 3 小时未来函数** — 信号在 fractal 形成的 3 小时**之前**就触发了, 等于偷看了未来 3 小时数据.

### 教训
1. fractal / swing / pivot 类**永远先回答"实盘可知时间"问题**
2. 任何 `find_swing(left=L, right=R)`, **confirm 时间必须 +R**
3. `right=0` 是唯一无 lookahead 的 fractal 形式 (但漏点)
4. **回测胜率 > 60% 必须立刻 challenge**

### 防止再犯
- 见 [[09-量化开发工作流SOP#防未来函数 SOP]] 第 3 章
- 见 [[01-工作原则与铁律#fractal/swing 实盘可知时间表]]

## 痛史 #2: Python 失真 285× (2026-05-10) 💀💀💀

### 症状
- Python 模拟: Plan A 全年 CAGR **+1432%** (14 倍)
- MT5 实测: CAGR 仅 **+5%**
- 失真倍数: **285×** (比 5/8 的 50× 痛史更严重)

### 根因
- Python 用 `sl_per_lot` proxy 估算 SL 风险, 没考虑真实 tick + 真实 spread + 真实 commission
- 平均估算让 lot size 偏小 → 实际单笔 risk 比 Python 算的小 1.6× → profit 累积放大

### 教训
**Python 任何模拟结果不可信**:
- PF 不可信
- Sharpe 不可信
- CAGR 不可信
- 白噪声击败率不可信
- 因子相关性矩阵不可信

### 防止再犯
**MT5-only workflow**:
- 所有参数 sweep → MT5 Strategy Tester
- 所有 OOS / walk-forward → MT5
- 所有 risk 评估 → MT5 (用真实 broker spread + tick)
- Python 只能用于: 信号生成 (factor generator) + 数据预处理 + audit (lookahead check)

memory: `feedback_python_distortion_285x.md` + `feedback_mt5_only_workflow.md`

## 痛史 #3: EA 编译成功 ≠ 跑成功 (2026-05-14) 💀

### 症状
- EA 编译 **0 errors 0 warnings**
- 部署上 demo
- 跑 24 小时 **0 trades**
- "silent failure"

### 根因
EA 内部某个 if 条件永远 false (e.g. signal 没读到 / handle 没初始化 / regime filter 全部 deny) — 编译时检测不到 runtime 问题.

### 教训
**EA 编译后必须立刻跑最小验证 backtest** 看到 `trades > 0` 才算完成.

### 10 步检查清单 (强制)
1. EA 编译 0 errors → record
2. 在 IC-tester 跑 1 周回测 (Model=2)
3. log 必须看到 `[FACTOR_DIST] <factor> allowed=N` 中 N > 0
4. log 必须看到至少 10 个 `order performed buy/sell` 记录
5. log 必须看到 `[RULEREGIME TESTER] trades=N` 中 N > 0
6. profit 非 0 (即使亏)
7. HTM 报告生成 (若 OnTester 不 crash)
8. 关键 input 参数 print 正确 (e.g. `RiskPct_*` 跟 INI 一致)
9. 无 `array out of range` / `division by zero` / `invalid handle` errors
10. backtest 结束 `automatical testing finished` (正常退出)

任一条 fail = EA 没真正跑成功, 不能 deploy.

## 痛史 #5: 跨 regime OOS 的浪费 (2026-05-24)

### 症状
- 跑 v8 在 2022.07-2024.06 段做"真 OOS"
- 结果: Profit -$4,889, Sharpe -0.73, MDD 76.95%
- 看起来 v8 死透
- 用户指出: 2024 前 XAU 是 chop / 低波动 regime, 完全不同的市场状态. v8 是趋势策略, 在 chop 段死正常. 这段验证**无意义**.

### 根因
- DeepSeek 推 5y walk-forward (textbook 做法), 但 textbook 假设 regime 稳定
- XAU 实际在 2025.03 突破 $3000 后**完全换 regime** (波动率 ×1.73, 价格区间翻倍)
- 在旧 regime 验证新 regime 策略 = 强求工具适应不存在的市场状态

### 教训
**OOS 验证必须 regime-aware**:
1. 先看 OOS 段的市场状态是否跟训练段一致
2. 不一致 = 跨 regime, 验证无效
3. 必须在同 regime 内做 walk-forward (即使段更短)

### 防止再犯
**OOS 段选择 SOP** (新增):
1. 训练段确认 (lock 时所有 sweep 涉及的时间)
2. 候选 OOS 段 = 训练段之前 + 之后未训练段
3. 各候选 OOS 段的市场指标对比 (价格区间 / 波动率 / 趋势性 / volume)
4. 选择市场指标跟训练段最接近的 OOS 段
5. 若所有候选都跨 regime → **不验证**, 只能 paper trade 等新数据

## 痛史 #12: Scalper20 v0.24 仓位 bug — $13,350 假利润全是 4.35× 杠杆 (2026-05-03) 💀💀

### 症状
- Scalper20 v0.24 backtest: **+$13,350 / WR 63.44% / PF 高**
- v0.24 之前 (v0.11-v0.21) 全是亏损 (-$5-7K)
- v0.24 突然盈利, 看似找到"金疙瘩"

### 根因
v0.22 引入: 在 `OpenTrade()` 加 `if(InpUseFixedSL)` 覆盖 SL 距离为 $10
```mql5
// OpenTrade (line 466)
if(InpUseFixedSL) {
   sl_pts = InpFixedSL_USD / g_point;   // 改成 $10
}
double sl = price - sl_pts*g_point;     // 实际 SL 放 $10 远
```

**但忘记同步 ArbitrateAndExecute 的 lot 计算**:
```mql5
// ArbitrateAndExecute (line 1042, 没改)
double sl_pts = MathMin(sl_pts_raw, atr_cap_pts);   // 仍用信号 SL ~$2.3
double lots = CalcLotSize(risk_pct, sl_pts);        // ← 用 $2.3 算 lot
```

数学:
- `lots = ($10,000 × 1%) / ($2.3 × $1) ≈ 0.43 lot` (按 $2.3 SL 算)
- 实际 SL = $10 → 单笔实际亏损 = 0.43 × $10 × 100 = **$430 = 账户 4.3%**
- **配置 1% 风险, 实际 4.35× 杠杆**

### 修复后 (v0.25, 保持 1% + 调 R/R 1.5)
| 维度 | v0.24 (带 bug) | **v0.25 (修复)** |
|---|---:|---:|
| 净盈利 | +$13,350 | **+$1,920** |
| WR | 63.44% | 48.66% |
| MDD | 47.48% | **11.61%** |
| 期望/笔 | +$32.32 | +$4.67 |
| 真实策略价值占 v0.24 利润 | - | **14.4%** |

### 教训
1. **lot 计算和 SL 放置必须用同一个距离** — 任何"覆盖路径"都要同步两侧
2. **每次 sweep 后必须主动删除 `.set` 文件** — 残留 set 会引入幽灵参数
3. **avg_loss 异常大 ≠ 高 R/R 信号** — 必须验证 lot 大小是否合理
4. **表面盈利不等于真实盈利** — 先看实际风险, 再看 PF

### 防止再犯
- EA 编译 + backtest 后, **手动验算单笔实际 loss vs 配置 risk%** 是否一致 (eg. 1% × $10K = $100 loss/trade, 实测 $100±20 才正常)
- 任何 SL/TP 路径覆盖代码必须 grep 全文找到所有 lot 计算位置同步
- 跑 backtest 前清理 `.set` 残留

## 痛史 #13: TripleResonance 三重共振没起到过滤 (2026-05-03)

### 症状
- 设计: HMA(20) + STC(80,27,50) + UT Bot(2.0, ATR6) 三重共振才入场
- 预期: 稀有但高确信信号 (~100/月)
- 实测: **1,492 笔** (vs Scalper20 411 笔, **3.6× 多**)
- PF 0.95, Sharpe -2.43, **DD 40.32%**

### 根因
**多指标共振 ≠ 过滤** — HMA / STC / UTBot 三个指标在 M5 上各自都产生大量假信号, 三个叠加后仍频繁触发 (因为它们之间相关性低, 都"看到"同一波动).

### 教训
- 多指标共振只在指标**测的是不同维度**时才过滤 (e.g. 趋势 + 波动 + 动量)
- 同维度叠加 (3 个动量指标) = 重复确认, 不是过滤
- **必须 cross-section 验证**: 设计共振时算共振触发率 (e.g. <100 笔/月才算稀有信号)

## 痛史 #14: HMM 离线 vs 在线分类器不一致 (2026-05-14 Master EA 案例)

### 症状
- v20260514_master_aplusplus 用 HMM 离线过滤生成 gated CSV
- EA 内置 5-feature 实时 regime 分类器
- 离线 HMM 标的 state 跟 EA 内在线分类器**不一致**
- `UseStateGate=false` (在 EA 内关掉在线分类器) 才能保留 70% alpha

### 根因
- 离线 HMM 用全段数据训, 在线分类器只用 t 时刻 features
- 两者数学定义不同 (HMM 是 sequential state, 5-feature 是 instant classification)
- 在线分类器误判会**杀掉 70% alpha**

### 教训
- **HMM 永远是 black-box training**, 实时部署要么用 Python HMM 服务推 CSV, 要么完全不用
- 不要混用"离线 HMM 训练 + 在线启发式分类器"
- v7+ EA 已经把 HMM 替换成 rule-based regime (iADX + iATR + iMA), 不需要训练数据, 但**用户对 regime filter 整体仍保守, lock 时 DisableRegimeFilter=true**

## 过拟合的 6 个常见来源 (按 v8 案例提炼)

## 🛠️ 技术栈最终选型

| 层 | 选型 | 备选 | 选它的理由 |
|---|---|---|---|
| **客户应用** | Coze 企业版 | Dify / 自研 | 老板见过豆包, 信任 |
| **核心 LLM** | DeepSeek V3 (API) | 豆包 Pro / 通义千问 Max | 便宜, 中文好, 合规 |
| **复杂推理 (后端隐用)** | Claude Sonnet 4.6 / Opus 4.7 | GPT-4 | 严肃推理质量必须高 |
| **图像理解** | 豆包视觉 / 通义千问 VL | GPT-4V | 国产合规 |
| **图像生成** | 即梦 / 通义万相 / FLUX | DALL-E | 国产合规 + 海报够用 |
| **RAG/向量库** | Coze 内置 / Dify 内置 | Milvus / pgvector | 不造轮子 |
| **工作流编排** | Coze 内置 / n8n | Dify | Coze 给客户看, n8n 给我们用 |
| **数据爬取** | 美团/大众点评 官方 API + Playwright RPA | 第三方 SaaS | 平台 API 有限, RPA 兜底 |
| **后端服务** | Python (FastAPI) + Celery | Node.js | 数据处理强 + 我们熟 |
| **数据库** | PostgreSQL + Redis | MySQL | JSON 字段灵活 |
| **PDF 生成** | WeasyPrint + Jinja2 | wkhtmltopdf | 排版精准 |
| **消息推送** | 企微机器人 / 钉钉机器人 webhook | 短信 / 邮件 | 客户主用 |
| **部署** | 阿里云 ECS / 火山云 ECS | 自建 | 国内合规 + 客户认 |
| **监控** | 自建简单监控 + 企微告警 | Grafana | 单客户够用 |
| **我们开发武器** | **Claude Code** | Cursor | 生产力 10× |

### 🗓️ Week 2-3: 核心模块开发

#### 模块 A: 设计部 AI

**A1. 套餐文案批量生成**
```python
# 工作流 (Coze 内 + Python 后端补强)
输入店铺信息 + 菜单
   ↓
[DeepSeek] 套餐策略推理 (基于行业历史 + 同类对标)
   ↓
[DeepSeek] 每套生成 5 个文案版本
   ↓
输出到飞书表格 / Coze 应用 UI
```
**开发量**: 3 天

**A2. 菜品图自动处理**
```python
# Python 后端
[豆包视觉 / 通义 VL] 检测主体 + 抠图
   ↓
[OpenCV / Pillow] 调色 / 调亮度 / 加水印
   ↓
归档到 OSS / 客户飞书云盘
```
**开发量**: 4 天

**A3. 海报批量出图**
```python
# 模板 + AI 文案适配
预制 20 个海报模板 (PSD / 即梦 prompt)
   ↓
[DeepSeek] 套餐文案适配各模板
   ↓
[即梦 / 通义万相] 批量出图 (各平台尺寸)
   ↓
质检 + 归档
```
**开发量**: 5 天

#### 模块 B: 数据运营 AI

**B1. 月报自动生成**
```python
# 定时任务 (每月 1 号 00:00)
for client in clients:
    数据 = 拉美团/大众点评 API
    分析 = DeepSeek 个性化分析 + 同类对标
    月报 = Jinja2 模板渲染 → WeasyPrint 出 PDF
    发送 = 企微机器人推送给客户 + 抄送运营
```
**开发量**: 6 天

**B2. 异常告警**
```python
# 定时任务 (每天 09:00)
for client in clients:
    今日数据 = 拉 API
    if 流量掉 > 30% or 差评新增 > 5 or 转化降:
        分析 = DeepSeek 原因推测 + 3 条建议
        推送企微到对应运营
```
**开发量**: 3 天

**B3. 下月套餐策略**
```python
# 月底跑 (每月 25 号)
分析本月每个套餐销量/利润/曝光
   ↓
[DeepSeek] 出下月建议
   ↓
运营审核界面 (Coze 应用)
   ↓
确认后一键上架到美团 (API / RPA)
```
**开发量**: 5 天

> [!info] Week 2-3 总开发量 = ~26 天
> 1 人开发约 30 天, 用 Claude Code 加速 ~50%, 实际 15-20 天.

## 🔧 关键工程注意点

### 1. LLM 输出质量保证

> [!warning] LLM 不稳定是最大隐患
> 同一个 prompt 同一个输入, LLM 可能输出不同质量结果. 客户员工拿到差结果直接对项目失去信任.

**对策**:
- **结构化输出**: 所有 LLM 调用强制 JSON Schema, 不接受自由文本
- **二次校验**: 关键字段 (价格/日期/数字) 用规则校验, 不合规重跑
- **多版本生成**: 套餐文案永远出 5 版给员工挑, 不是出 1 版
- **fallback**: LLM 出错时降级到模板 + 提示员工人工补

### 2. 数据接入的脏数据陷阱

> [!danger] 客户公司 80% 的数据是脏的
> Excel 列名乱写, 客户名重名, 时间格式 8 种, 数字带"约"字, 等等.

**对策**:
- **第 1 周必做数据质量评估**, 不评估直接开发必翻车
- **数据清洗模块单独开发**, 不要嵌在业务逻辑里
- **AI 容错**: 让 DeepSeek 处理脏输入也能出合理结果 (这是 AI 比传统软件强的地方)

### 3. 工作流编排的可观察性

> [!warning] Coze / Dify 是黑盒
> 跑炸了客户员工只看到"系统卡了", 你不知道哪个节点出问题.

**对策**:
- **每个节点打日志**: 输入/输出/耗时/错误码
- **集中日志查询**: 后端 PostgreSQL 存所有日志, 客户出问题秒查
- **失败重试**: 网络故障/限流自动重试 3 次
- **告警**: 任何节点失败推企微给我们

### 4. 模型 API 限流和成本

> [!info] DeepSeek 便宜但有限流
> 80 客户 × 每天平均 50 次调用 = 4000 次/天. 大模型限流 QPS 20-100.

**对策**:
- **请求合并**: 同类任务批量处理 (一个 batch 处理 20 客户)
- **缓存**: 模板类输出缓存 (同店铺类型套餐文案模板)
- **混合模型**: 简单任务 DeepSeek V3, 复杂任务后端混 Claude (客户不知, 但质量更稳)
- **成本监控**: 每天看 API 消耗, 月预算 1000-3000 元 (单客户)

### 5. 客户系统对接的兼容性

> [!warning] 客户的美团账号/企微账号需要授权
> 涉及客户敏感数据, 必须合规授权 + 数据隔离.

**对策**:
- **OAuth 授权**: 用美团/企微官方 OAuth, 不要客户给密码
- **数据隔离**: 每个客户单独数据库 schema, 不混
- **加密存储**: 所有客户 token / 密钥 AES 加密
- **审计日志**: 每次访问客户数据记录, 老板能查

## 🚀 部署架构

```
┌─────────────────────────────────────────────────┐
│        阿里云华东 ECS (主)                       │
│  ┌─────────────────────────────────────────┐    │
│  │ Nginx (反向代理 + SSL)                   │    │
│  └─────────────┬───────────────────────────┘    │
│  ┌─────────────▼───────────────────────────┐    │
│  │ FastAPI 服务 (Python 后端)               │    │
│  │ - 业务 API                                │    │
│  │ - LLM 调用封装                            │    │
│  │ - 数据爬取/接入                            │    │
│  └─────────────┬───────────────────────────┘    │
│  ┌─────────────▼───────────────────────────┐    │
│  │ Celery + Redis (任务队列)                 │    │
│  │ - 月报生成定时                            │    │
│  │ - 异常告警定时                            │    │
│  │ - 批量处理任务                            │    │
│  └─────────────┬───────────────────────────┘    │
│  ┌─────────────▼───────────────────────────┐    │
│  │ PostgreSQL                               │    │
│  │ - 客户数据 (按 schema 隔离)               │    │
│  │ - 业务流水                                │    │
│  │ - 审计日志                                │    │
│  └──────────────────────────────────────────┘    │
└─────────────────────────────────────────────────┘
              ↓ 调用
┌─────────────────────────────────────────────────┐
│  外部服务                                         │
│  • DeepSeek API (阿里云内网)                     │
│  • 豆包 API                                       │
│  • 美团/大众点评 API                              │
│  • 企微 / 钉钉 webhook                            │
└─────────────────────────────────────────────────┘
```

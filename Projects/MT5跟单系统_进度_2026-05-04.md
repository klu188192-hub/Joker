## 核心特性

- **N:M 关系**: 1 master → 多 slave / 多 master → 1 slave (用 magic 区分)
- **balance ratio 缩放**: `slave_lot = master_lot * (slave_balance / master_balance)`
- **fixed ratio 缩放**: 固定倍数 (用于测试)
- **max_lot 风控护栏**: 单笔上限 (防止误操作 50 lot)
- **min_balance_threshold**: slave 资金不足停止接单
- **支持 OPEN / CLOSE / MODIFY / PARTIAL_CLOSE** 全部改单
- **position_map 持久化**: master_ticket ↔ slave_ticket, 重启不丢
- **WS 自动重连**: agent 断线 sleep 3s 重连
- **跨设备**: Tailscale 内任何设备能跑 agent

## 数据流

1. master agent 每 100ms 查 `mt5.positions_get()` → snapshot
2. diff 上次 snapshot → 检测到 OPEN/CLOSE/MODIFY/PARTIAL_CLOSE
3. 发 trade.event 到 coordinator
4. coordinator 查路由表, 对每个 enabled slave:
   - 计算 lot (按 ratio_mode)
   - 查 position_map (CLOSE/MODIFY 用)
   - 发 copy.order 到 slave agent
5. slave agent 收 → MT5 order_send → 回 ack
6. coordinator 收 ack:
   - OPEN 成功 → 写 position_map (master_ticket ↔ slave_ticket)
   - CLOSE 成功 → 标 closed=1
   - 写 events_log

## 已知约束

1. **Python MT5 module 是 DLL singleton** → 1 进程对应 1 终端 → 同设备多 MT5 → 多 agent 进程
2. **Coordinator 必须先启** (agent 重连 sleep 3s, 多次失败也不死)
3. **Mock test 不真下单**, 只验证消息流 + DB 写入
